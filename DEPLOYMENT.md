# Deployment

AcousticLab is a fully client-side application: every screen prerenders to static
HTML, there is no server runtime, no database and no API. Deploying it is therefore
just hosting static files over HTTPS.

**HTTPS is not optional.** Browsers refuse `getUserMedia` outside a secure context,
and service workers need one too. `localhost` counts as secure; a bare IP address on
your LAN does not.

---

## 1. Push to GitHub

```bash
cd acousticlab
git init
git add .
git commit -m "AcousticLab: calibrated smartphone acoustic measurement tool"
git branch -M main
git remote add origin https://github.com/<you>/acousticlab.git
git push -u origin main
```

`.gitignore` already excludes `node_modules/`, `.next/`, `out/`, test artefacts and
the generated static assets (`public/icons/`, `public/worklets/`, `public/sw.js`).
Those are regenerated by `prepare:static`, which runs automatically before `dev` and
`build`, so nothing generated needs to be committed.

There are no secrets to configure. If you ever add any, use environment variables and
never commit them.

### Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request:

1. `npm ci`
2. `npm run lint`
3. `npm run typecheck`
4. `npm test` — the DSP unit tests
5. `npm run build`
6. `npx playwright test` — end-to-end against the production build

The Playwright job uses Chrome's fake audio capture device, so the full measurement
chain is exercised headlessly with no microphone hardware.

## 2. Deploy to Vercel

### Through the dashboard

1. <https://vercel.com/new> → **Import Git Repository** → choose your repository.
2. Vercel detects Next.js. Leave everything at the defaults:
   - Framework preset: **Next.js**
   - Build command: `npm run build`
   - Output directory: *(leave blank)*
   - Install command: `npm ci`
   - Node version: 20 or later
3. No environment variables are needed.
4. **Deploy.**

You get `https://<project>.vercel.app` with a valid certificate. That URL works for
measurement immediately.

### Through the CLI

```bash
npm i -g vercel
vercel          # preview deployment
vercel --prod   # production
```

### What Vercel does with it

Every route is static, so it is all served from the edge with no serverless function
invocations. The free tier is sufficient; nothing in the core application requires a
paid plan.

Two headers are configured in `next.config.ts`:

- `/sw.js` → `no-cache, no-store, must-revalidate`, so a new service worker is always
  discovered rather than being served from a stale HTTP cache.
- `/worklets/*` → `max-age=0, must-revalidate`, for the same reason with the compiled
  AudioWorklet.

### Custom domain

Vercel project → **Settings → Domains** → add your domain and follow the DNS
instructions. The certificate is issued automatically. A custom domain is worth having
because microphone permission is remembered per origin: moving origins means granting
permission again, and a stable domain means a stable calibration history in IndexedDB.

## 3. Other static hosts

Any host that serves static files over HTTPS works. Build with:

```bash
npm run build
```

Then serve the `.next` output through `npm start`, or configure your platform's
Next.js adapter. Cloudflare Pages, Netlify and Azure Static Web Apps all support
Next.js directly.

If you need a plain directory of files, add `output: 'export'` to `next.config.ts`
and build; `out/` is then self-contained. Everything in AcousticLab is compatible with
static export — no route uses server rendering, dynamic parameters or server actions.
The only thing to check afterwards is that your host applies the two cache headers
above.

Self-hosting with Docker:

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/.next ./.next
COPY --from=build /app/public ./public
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/package.json ./
EXPOSE 3000
CMD ["npm", "start"]
```

Put it behind a reverse proxy that terminates TLS.

## 4. Install on Android

1. Open the HTTPS URL in **Chrome** on Android. Edge works too. Firefox on Android
   does not support AudioWorklet reliably enough for measurement.
2. Chrome menu (⋮) → **Add to Home screen** → **Install**.
3. Launch from the home screen. It opens standalone, portrait, with no browser UI.
4. On first measurement, tap **Open microphone** and **Allow**.

Grant permission permanently rather than "only this time", otherwise you will be
prompted on every launch.

### Confirm the installation is sound

| Check | Where |
| --- | --- |
| Microphone live | Status bar shows `MIC ✓` |
| Sample rate | Status bar shows `48 kHz` |
| Processing disabled | Diagnostics → all three flags `disabled` |
| Worklet loaded | Diagnostics → AudioWorklet support `yes` |
| Offline ready | A confirmation appears after the service worker caches |

### Verify offline operation

1. Open the app and visit each screen once while online.
2. Enable airplane mode.
3. Relaunch from the home screen.

Everything should work: measurement, analysis, calibration, sessions, exports. If a
screen shows an offline notice, it had not been cached yet — reconnect, visit it once,
and it will be available thereafter.

### Keep the measurement alive

Android suspends the audio engine when the screen locks. AcousticLab requests a screen
wake lock while measuring (Settings → **Keep the screen awake while measuring**,
enabled by default) and, if the engine is suspended anyway, stops the clock rather
than integrating silence and tells you in the status bar. Also disable battery
optimisation for Chrome if you intend to run long measurements.

## 5. Updates

`scripts/build-sw.mjs` stamps each build with a new cache version, so a deploy
invalidates the old cache.

On the user's device:

1. The new service worker installs in the background.
2. If a measurement is running, the update **waits**. Activating it reloads the page,
   which would interrupt the measurement.
3. Otherwise a prompt offers **Update now**, which activates the new worker and
   reloads.

The page is never reloaded on the *first* service worker activation, only when an
update replaces a worker that was already in control.

To force an update during development: Chrome DevTools → Application → Service Workers
→ **Unregister**, then reload. Or Settings → **Delete all measurement data**, which
also clears the caches.

## 6. Troubleshooting

**"Microphone access requires a secure context"**
You are on plain HTTP and not on `localhost`. Use HTTPS. For testing against a
development machine from a phone, use a tunnel:

```bash
npx localtunnel --port 3000
# or
ngrok http 3000
```

**Microphone permission was denied and the prompt never returns**
Chrome on Android: tap the icon left of the address bar → **Permissions** →
**Microphone** → Allow, then reload. For an installed PWA: Android Settings → Apps →
AcousticLab → Permissions.

**"This browser does not support AudioWorklet"**
Use Chrome or Edge. Check the diagnostics screen for what was detected.

**The app loads but shows no level**
Check the status bar. `MIC –` with no tick means no samples have arrived: another
application may hold the microphone, or the track is muted by the system. Check
diagnostics → Track state.

**The build fails with a worker crash**
`next.config.ts` caps build parallelism at four workers because one worker per logical
CPU can exhaust thread or commit limits on machines with many cores and a small paging
file. If it still fails, lower `experimental.cpus` further.

**Icons or the worklet are missing after deployment**
They are generated by `prepare:static`, which runs as `prebuild`. If your platform
runs `next build` directly instead of `npm run build`, change the build command to
`npm run build`.

**`sw.js` returns 404**
It is generated into `public/` at build time and is gitignored deliberately. Confirm
the build command is `npm run build` so `prebuild` runs.

## 7. Deployment checklist

- [ ] `npm run verify` passes locally (lint, typecheck, unit tests, build)
- [ ] `npm run test:e2e` passes locally
- [ ] Pushed to GitHub and CI is green
- [ ] Deployed to Vercel and the HTTPS URL loads
- [ ] `/manifest.webmanifest` returns valid JSON
- [ ] `/worklets/meter-processor.js` returns JavaScript
- [ ] `/sw.js` returns JavaScript with `no-store`
- [ ] Installed on an Android phone from the home screen
- [ ] Microphone permission granted and `MIC ✓` shown
- [ ] Diagnostics confirms AGC, noise suppression and echo cancellation disabled
- [ ] Offline relaunch works with airplane mode on
- [ ] A calibration profile created and a single-point calibration performed
- [ ] A test measurement saved, and its report and CSV exported
